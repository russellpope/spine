## Problem

Every subagent dispatch in the estate is a hand-written one-off brief under
`.superpowers/sdd/` (counted 2026-09-02: 286 in spine, 243 in maikanban, 318
in maipipe). The contract text each brief carries — requirements attack,
evidence demands, ticket-id correlation, dispatch effort declaration, the
reviewer floor — is duplicated by hand and drifts per author, while spine
already ships every other document template via `go:embed` with generation
migrations. The briefs are the estate's most-duplicated, least-governed
artifact.

Source: fusion-harness borrow hitlist item 3
(`docs/research/2026-08-26-fusion-harness-borrow-hitlist.md`), whose
reference implementation keeps every agent contract as a `SYSTEM_PROMPT_*.md`
/ `USER_PROMPT_*.md` file that code interpolates but never contains.

## Fix

Add a `dispatch/` template family to `templates/current/`: a worker brief, a
reviewer brief, and a relay-builder brief. Each carries the invariant
contract text (dispatch declaration line, ticket-id token, requirements-attack
step, evidence rules) with placeholders for the variable parts. Ship them
like every other managed file: stamped, regenerated by `spine update`,
predecessors' dropped lines appended to the superseded set. Decide in the
PRD whether the rendered copies live under `.superpowers/sdd/templates/` or
are consumed by the claude-team skill directly from the binary.

## Acceptance criteria

- [ ] `spine init` and `spine update --write` render the three brief templates into the chosen location, stamped like other managed files.
- [ ] A hand edit to a rendered brief is reported by `spine update` the same way as any other managed file (skipped unless forced).
- [ ] The template test suite covers the new family (generation bump, superseded set).
- [ ] One real dispatch in spine uses a rendered brief end to end, and `spine audit routing` attributes it.
