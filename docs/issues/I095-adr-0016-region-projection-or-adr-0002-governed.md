## Problem

Filed 2026-08-19 from `docs/research/2026-08-19-gate-pack-region-ownership-analysis.md`.

Three artifacts describe the region's preservation rule and no two agree:

- **ADR 0016 (Decision)** — the region is "regenerated by `spine update` under
  ADR 0002's rules: content matching the shipped default is inherited and
  refreshed; **edits inside the region are unrecognized and reported, never
  silently kept**."
- **ADR 0002 (Decision)** — "an extracted value equal to its own generation's
  rendered default is not a user choice and takes the new default; **only
  divergent values survive**."
- **`internal/update/gatepack.go:238-243`** — cites *ADR 0002* as the
  justification for the opposite: a changed `gate_pack_config` value "refreshes
  silently". And `unrecognizedRegionLines` (`:244-288`, env at `:277-284`)
  accepts any quoted value for a known `SPINE_GATE_*` name, so a divergent env
  value is neither reported nor kept — it is silently overwritten by the next
  `spine update --write`, no `--force` required (reproduced 2026-08-19 on a
  clean checkout).

So ADR 0016 promises reporting the implementation does not do, and the
implementation cites an ADR that says the reverse of what it does.

This is the gating decision for the region work: reading (A) makes preservation
machinery unnecessary, reading (B) requires a record of the last render.

## Fix

Owner call between two coherent readings, recorded as an ADR 0016 amendment:

**(A) Pure projection.** The region is a rendering of WORKFLOW.md; no value
inside it is ever a user choice; ADR 0002's preservation rule does not apply.
Amend ADR 0016 to "edits inside the region are discarded on refresh; the plan
diff shows what drops", and stop `gatepack.go` citing ADR 0002 for it. This is
what the code does today, and it makes value-evident recognition wrong by
definition (see the research doc's withdrawn recommendation).

**(B) Genuinely ADR-0002-governed.** Divergent values must survive and be
reported. That requires knowing what spine *last rendered* — a legitimate
WORKFLOW.md config change and a region hand-edit are otherwise indistinguishable
(proved live: both produce Pending, zero unrecognized, the same `-/+` env diff).
The cheapest record that survives clone, worktree and branch switch is **in-band
on the marker line spine already rewrites**: `# spine:begin gate-pack go@1
<fingerprint>`. It is a comment, so maipipe's `deny_unknown_fields` is untouched.
Do **not** use a gitignored sidecar.

Under either reading, the D10 message should distinguish "stale — WORKFLOW.md
changed" from "region edited", since today both render as staleness.

## Resolution (2026-08-20) — owner call: (A) pure projection

The region is a rendering of WORKFLOW.md; no value inside it is a user
choice; ADR 0002's choice-vs-default rule does not apply to it. No
fingerprint, no last-render record, no sidecar. The (B) box above stays
unticked by design.

- **ADR 0017** supersedes ADR 0016 (`spine adr new --supersedes 16`; 0016
  flipped to `Superseded by 0017`, body untouched). 0017 carries the whole
  decision as one record — 0016's region ownership, I091's render
  correction, and reading (A) as the Decision: edits discarded on refresh,
  the `spine update` plan diff is the review surface. Rationale section
  below the rule: a hand-edit and a legitimate `gate_pack_config` change
  produce byte-identical plan states, so "preserve divergent values" is
  undecidable without a last-render record, and every region knob already
  has a WORKFLOW.md key. Explicit carve-out: `unrecognizedRegionLines`
  stays as ADR 0002's generic shape stop (`--force` before the drop), not
  preservation. Recorded as a superseding ADR, not an in-place note,
  because this reverses a sentence of 0016 (`docs/adr/README.md`).
- `internal/update/gatepack.go` `unrecognizedRegionLines` doc comment now
  cites ADR 0017 for the silent value refresh, and names the
  shape matcher as ADR 0002's generic unrecognized-edit stop, not
  preservation. No code change.
- `docs/specs/2026-08-18-local-harness-conventions-design.md` §Rendering:
  "under ADR 0002 rules" → projection wording, dated.
- `internal/update/gatepack_test.go`
  `TestGatePackEditedEnvValueRefreshesWithoutForce` pins the decided
  behaviour: a hand-edited `SPINE_GATE_FIXTURE_MANIFEST` value plans as
  Pending with zero unrecognized lines, the plan diff shows the `-`/`+`
  env rows, and `--write` reverts it without `--force`. Negative control:
  making the env branch report the line fails the test
  (`state=2 unrec=[env = { … "docs/elsewhere.md" }]`).
- Evidence: `go vet ./...` clean; `make test` → all 18 packages `ok`.
- **Why the D10 message cannot yet distinguish "WORKFLOW.md changed" from
  "region edited"** (the acceptance line above asks for the split *or* for
  I095 to record why it cannot): telling the two causes apart requires
  knowing what spine last rendered, and reading (A) deliberately keeps no
  such record — no fingerprint, no sidecar, nothing in-band on the marker
  line. Both causes therefore reach D10 as the same byte-level delta, and a
  message claiming to name the cause would be guessing. The split becomes
  implementable only under a decision that reintroduces a last-render
  record (reading (B)). Reasoning also carried in ticket I099 and in the
  D10 doc comment in `internal/doctor/doctor.go`.
- Out of scope here, left to their owners: the D10 message split
  (I099 / concurrent doctor team); whether the region header comment should
  mention the plan diff (changing it re-renders every adopter's bytes and
  costs a maipipe `approve-definition`, see the research doc).
